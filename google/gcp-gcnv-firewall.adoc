= Firewall
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Google Cloud NetApp Volumes stellt mehrere TCP-Ports bereit, um NFS- und SMB-Freigaben bereitzustellen:

* https://docs.cloud.google.com/netapp/volumes/docs/connect-clients/connect-nfs-clients#firewall_rules_for_nfs_volumes_access["Für den NFS-Zugriff erforderliche Ports"^]
* https://docs.cloud.google.com/netapp/volumes/docs/connect-clients/connect-smb-clients#firewall_rules_for_smb_volumes_access["Für den SMB-Zugriff erforderliche Ports"^]


Zusätzlich erfordern SMB, NFS mit LDAP einschließlich Kerberos und Dual-Protokoll-Konfigurationen Zugriff auf eine Windows Active Directory-Domäne. Active Directory-Verbindungen müssen  https://docs.cloud.google.com/netapp/volumes/docs/configure-and-use/active-directory/create-ad-policy["konfiguriert"^] pro Region eingerichtet werden. Active Directory-Domänencontroller (DCs) werden mithilfe von https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-adts/7fcdce70-5205-44d6-9c3a-260e616a2f04["DNS-basierte DC-Erkennung"^] unter Verwendung der angegebenen DNS-Server identifiziert. Alle zurückgegebenen DCs werden verwendet. Die Liste der infrage kommenden DCs kann durch die Angabe eines Active Directory-Standorts eingeschränkt werden.

Google Cloud NetApp Volumes greift mit IP-Adressen aus dem CIDR-Bereich zu, der mit dem `gcloud compute address` Befehl zugewiesen wurde, während https://docs.cloud.google.com/netapp/volumes/docs/plan-and-prepare/networking#configure_private_services_access["Onboarding der Google Cloud NetApp Volumes"^]. Sie können diesen CIDR-Bereich als Quelladressen verwenden, um eingehende Firewalls für Ihre Active Directory-Domänencontroller zu konfigurieren.

Active Directory Domain Controllers müssen https://docs.cloud.google.com/netapp/volumes/docs/plan-and-prepare/security-considerations["Ports für die Google Cloud NetApp Volumes CIDRs verfügbar machen, wie hier erwähnt"^].
